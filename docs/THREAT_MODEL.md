# Threat model and claim boundary

- Interested participant changes responsibilities after consent: no edit method;
  create a new digest-bound workspace and obtain fresh responder consent.
- Outsider finalizes an open thread: participant check before nondeterminism/mutation.
- Wrong leader assigns duty: independent substantive validator must match both kinds
  and exact source identity/quotes. Genuine live model resistance remains unproven.
- Scopes or sources contain evaluator instructions: prompt treats them as untrusted
  data; direct public-path adversarial tests and real model probe required.
- Fake valid digest: contract calculates projection digest from fetched authoritative
  bytes; neither a user report nor UI-provided hash can authorize dispatch.
- Task bypass: exact sender, predecessor, phase and revision checked in contract.
  Self-acceptance, cross-workspace ID, duplicate advisory and terminal replay blocked.
- Cancellation race: complete incident/workspace equality checked after consensus;
  no clock or indefinitely held funds.
- Official API evolves or rate-limits: UNRESOLVED without tasks, bounded completed
  retries or cancellation. No claim of continuous vulnerability monitoring.
- Handover lies: records declarations and counterparty acknowledgement only. It
  cannot demonstrate installed versions, test execution, remediation or node safety.
- Either participant can cancel: this is an explicitly consented operations workflow,
  not enforced employment, slashing, service availability or incident resolution.

Local test success is not live runtime proof. Read-only UI is not wallet signing.
